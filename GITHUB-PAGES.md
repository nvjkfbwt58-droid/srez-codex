# Срез на GitHub Pages

## Что публикуется

Версия приложения для работы в браузере без Node-сервера: аналитика, сегменты, кампании, 12 шагов сценария, студия, загрузка материалов, ручные правки, PNG/JSON, локальная касса и результаты демонстрации.

Дизайны, материалы, профили бренда и импорт сохраняются в браузере каждого посетителя. Они не становятся общими для команды и не передаются в репозиторий. Очистка данных сайта удаляет локальные изменения; для переноса используйте экспорт и отдельно сохраните загруженные материалы. JSON дизайна ссылается на материалы и не содержит их байты.

**Новая AI-генерация и анализ стиля на Pages не выполняются.** Они требуют отдельного сервера. Рабочий серверный вариант проекта сохранён и по-прежнему запускается через `pnpm dev` / `pnpm build` / `pnpm start`. Секреты API в статическую сборку не добавляются.

## Публикация из репозитория

1. Загрузите исходники проекта в репозиторий GitHub. `node_modules`, `.env`, `storage` и локальные результаты сборки исключены из Git.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. После отправки в ветку `main` workflow **Publish Srez to GitHub Pages** запускает тесты, собирает сайт и публикует его. Его также можно запустить вручную в **Actions → Run workflow**.
4. Итоговая ссылка появится в завершённой задаче публикации и в **Settings → Pages**.

Приложение использует адреса вида `/#/overview`, поэтому переход по прямой ссылке, перезагрузка и кнопки назад/вперёд не требуют серверного перенаправления. Изображения, шрифты и worker-файлы используют относительные пути и работают в подпапке репозитория.

## Проверка сборки

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm run build:pages
pnpm run preview:pages
```

Результат — папка `dist-pages`. Её содержимое также можно публиковать как готовый статический сайт без сборки на GitHub. Превью работает на порту 5180.

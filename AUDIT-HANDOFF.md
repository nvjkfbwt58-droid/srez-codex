## 2. Реальная архитектура

Frontend: React 19, TypeScript, Vite, React Router, Zustand; Motion/WAAPI и CSS; SVG-графики; TanStack Table по запросу. `src/domain.ts` содержит детерминированный генератор, расчёты, сегменты, экономику, назначения и локальную кассу. `src/seed.worker.ts` создаёт аналитику в Worker.

Аналитические данные находятся **в браузере**, а не в серверных таблицах продаж: IndexedDB (`srez-seed-v1`, `srez-import-v1`). Кампании, сегменты, демо-события, настройки и история — localStorage `srez-workspace-v1`. GitHub Pages использует HashRouter, `src/pagesStore.ts` и IndexedDB `srez-pages-library-v1` для дизайнов и материалов. Состояние не общее между посетителями.

Backend: Node 24, Express 5, встроенный SQLite, Zod, Sharp, PDF.js, OpenAI SDK. `server/index.ts` запускает HTTP на loopback; `server/app.ts` содержит API, загрузки и задания. `server/store.ts` хранит JSON-документы в SQLite, `DATA_DIR/assets` — байты файлов. Основные виды записей: brand, version, asset, coupon, design-version, job, variant; отдельно idempotency. Ключ `(kind,id)` не включает brand. Внешняя очередь и отдельная БД аналитики отсутствуют.

Pages — только статический frontend: Node/API туда не развёрнуты. Локальный backend сохранён в этом же репозитории.

## 3. Установка и фиксация версии

Проверенная среда: Node **24.19.0**, pnpm **11.19.0**. `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`, конфиги TypeScript/Vite и сборка сервера включены. Зависимости менять перед первым проходом не нужно.

```sh
git clone https://github.com/nvjkfbwt58-droid/srez-codex.git srez-audit
cd srez-audit
# Перед запуском переключиться на полный SHA из сопроводительного сообщения:
git checkout --detach <AUDIT_COMMIT_SHA>
git rev-parse HEAD
node --version
pnpm --version
pnpm install --frozen-lockfile
```

В команде checkout заменить `<AUDIT_COMMIT_SHA>` на переданный SHA. Не копировать `.env`, `storage`, выгрузки клиентов или браузерный профиль из рабочего окружения.

## 4. Отдельная тестовая БД и демо-данные

`scripts/audit-seed.ts` **всегда** создаёт новый случайный каталог в системной временной папке. Не принимает путь к существующей БД, не читает `.env`, не открывает HTTP-порт и не подключает AI. Он:

1. создаёт `srez.sqlite` и `assets`;
2. сверяет таблицы и первичные ключи с `db/migrations/001-initial.sql`;
3. загружает три синтетических бренд-профиля и два тестовых купона;
4. пишет `demo-dataset.json`, `audit-manifest.json`, пустой `empty.env`;
5. проверяет 110 873 операции и выручку 2 281 824 350 копеек.

Команды для bash/zsh (на Windows — WSL):

```sh
AUDIT_MANIFEST="$(mktemp "${TMPDIR:-/tmp}/srez-audit-manifest.XXXXXX")"
pnpm exec tsx scripts/audit-seed.ts > "$AUDIT_MANIFEST"
cat "$AUDIT_MANIFEST"
AUDIT_DATA_DIR="$(node -e 'console.log(JSON.parse(require("node:fs").readFileSync(process.argv[1],"utf8")).directory)' "$AUDIT_MANIFEST")"
DOTENV_CONFIG_PATH="$AUDIT_DATA_DIR/empty.env" OPENAI_API_KEY= IMAGE_PROVIDER=none DATA_DIR="$AUDIT_DATA_DIR" PORT=4178 pnpm dev
```

Открыть http://127.0.0.1:5178/overview **в отдельном новом браузерном профиле или приватном окне**. Это необходимо также для изоляции IndexedDB/localStorage. При первом открытии Worker автоматически загрузит тот же синтетический набор. JSON в каталоге аудита предназначен для сверки, это не файл CSV-импорта.

Порты фиксированы: frontend 5178, backend 4178. Если они заняты, не останавливать чужой/рабочий процесс; выполнять аудит в отдельной среде. Изменение только PORT недостаточно: proxy и проверка Origin содержат эти порты. `empty.env` и явно пустой ключ исключают случайное использование ключа из текущей оболочки. `DATA_DIR` указывает только на новый тестовый каталог.

История: 17.05–13.09.2026; демо-время 14.09.2026 10:00 Москва; основной период 17.08–13.09. 12 магазинов, 16 000 синтетических покупателей, 192 товара. Seed 1042026, схема браузерных данных 3. Это не пользовательские выгрузки.

### Схема и миграции

Полный начальный SQL: `db/migrations/001-initial.sql`. Рабочий сервер пока выполняет эквивалентный `CREATE TABLE IF NOT EXISTS` непосредственно в `server/store.ts`; SQL-файл — воспроизводимая начальная миграция для аудита, не новый механизм обновлений. Исторических ALTER-миграций, таблицы версий миграций и downgrade нет. Браузерный `schemaVersion=3` не является версией SQLite. Изменять или мигрировать рабочую БД для аудита не требуется.

## 5. Запуск и проверки

```sh
pnpm test
pnpm build
pnpm run build:pages
pnpm run preview:pages
```

`pnpm test`: расчёты, импорт, сервер, PDF, адаптер AI с тестовым транспортом, SSR компонентов, графики, кэши, сохранение. Серверные тесты создают отдельные временные каталоги и слушают случайные loopback-порты; рабочий DATA_DIR не используют. Браузерные E2E: отдельно, только при работающем тестовом сервере:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

Полный E2E не был выполнен. `e2e/app.spec.ts` содержит старые селекторы, в том числе неоднозначную кнопку «Все 12 магазинов»; считать сценарий подготовленным, а не гарантированно проходящим. При актуализации сохранять смысл проверок.

Production локально, после `pnpm build`, с тем же отдельным каталогом:

```sh
DOTENV_CONFIG_PATH="$AUDIT_DATA_DIR/empty.env" OPENAI_API_KEY= IMAGE_PROVIDER=none DATA_DIR="$AUDIT_DATA_DIR" PORT=4178 pnpm start
```

Приложение и API будут на http://127.0.0.1:4178. Не запускать одновременно с dev-backend на том же порту. Pages-preview: http://127.0.0.1:5180/#/overview, отдельное браузерное хранилище этого origin.

## 6. Переменные окружения

Пример без секретов: `.env.example`. Ни реальные ключи, ни БД в репозиторий не включены.

| Переменная | Фактическое назначение / значение по умолчанию |
|---|---|
| OPENAI_API_KEY | Серверный секрет, в примере пусто; для базового аудита пусто |
| IMAGE_PROVIDER | `none` отключает AI; при наличии ключа любое другое значение создаёт OpenAI-адаптер; пример `openai` |
| IMAGE_MODEL | `gpt-image-2.5-sunburst`, точная строка текущего кода, доступность не подтверждена |
| BRAND_ANALYSIS_MODEL | `gpt-4.1`, доступность для аккаунта не подтверждена |
| PORT | 4178, прослушивание 127.0.0.1 |
| DATA_DIR | `./storage`; для аудита обязательно новый временный каталог |
| MAX_JOBS_PER_DAY | 20, лимит единиц задания по сети |
| MAX_CONCURRENT_JOBS | 2, одновременно активных заданий по сети |
| NODE_ENV | `production` включает раздачу dist и SPA fallback; `pnpm start` задаёт его сам |
| DOTENV_CONFIG_PATH | Поддерживается dotenv; в аудите путь к созданному пустому empty.env |
| GITHUB_SHA | Только сборка Pages: полный SHA в version.json; не настройка приложения |

Секретных `VITE_*` переменных нет. `MODE`/`BASE_URL` предоставляет Vite при сборке.

## 7. Роли, аккаунты и две сети

**Настоящие аккаунты создать нельзя: регистрации, паролей, сессий, SSO, RBAC и серверной проверки пользователя нет.** Имя «Анна Соколова» в интерфейсе — фиксированная демо-персона. Настройки → «Демонстрационная роль»: owner / Владелец, marketer / Маркетолог, manager / Управляющий. Для трёх независимых UI-состояний использовать три чистых браузерных профиля. Переключение роли не является проверкой прав: ограничивающие подписи в UI нельзя считать серверной защитой.

Две сети для проверки бренд-данных уже создаются автоматически: `kvartal` / Квартал 12 и `copper` / Медный двор (также есть `lemon`). Тестовая подготовка добавляет купоны `AUDIT-kvartal`, `AUDIT-copper`. Профили выбираются в «Стиль сети», а тема купона — в студии → Шаблоны. API доступен по `/api/brands`, `/api/brands/kvartal`, `/api/brands/copper`, `/api/coupons/AUDIT-kvartal`, `/api/coupons/AUDIT-copper`.

Это изоляция принадлежности материалов/вариантов по brandId, **не полноценная мультиарендность**. Нет отдельных пользователей/магазинов/аналитических наборов двух организаций. API не аутентифицирует клиента; GET материалов/купонных данных не следует считать защищённым. В исходниках можно проверить отказ для чужого asset/variant, но не заявлять доказанную межорганизационную безопасность.

## 8. AI-интеграции

`server/providers.ts`: официальный OpenAI SDK; анализ бренд-референсов через Responses API и структурированный ответ Zod; изображения через `images.generate`, при референсах или текстовой правке через `images.edit`. Условия, текст, логотип и QR накладываются интерфейсом отдельно. Задания/версии/идемпотентность хранятся в SQLite; выполняются в процессе Node. После рестарта незавершённые работы помечаются interrupted и не повторяются автоматически. SDK maxRetries=0.

Для live-проверки нужен отдельный тестовый ключ с доступом к реально доступным моделям, квота и разрешение на платные запросы. Записать ключ в приватный файл вне репозитория в каталоге аудита, передать его через DOTENV_CONFIG_PATH; IMAGE_PROVIDER=openai. Проверить `/api/status`, затем загрузить только искусственные референсы, подтвердить стиль и выполнить генерацию/правку. Статус connected показывает наличие адаптера, а не успешный вызов провайдера. Имена моделей выше отражают код, а не гарантию текущей доступности.

Без ключа новая генерация возвращает честную ошибку; готовые изображения помечены «Пример». На GitHub Pages новые AI-задания недоступны. «Помощник» — локальный разбор 12 намерений в `src/assistant.ts`, не обученная на сети LLM, не RAG и не серверный чат.

## 9. Известные ограничения и незавершённое

- Нет production-авторизации, реальных аккаунтов и защищённой мультиарендности; роли демонстрационные.
- Нет реальной кассовой интеграции, доставки купонов в чужое приложение, рассылок, платежей и общей командной синхронизации. PNG/JSON — экспорт, касса — локальная симуляция.
- Сервер хранит дизайн, браузер — кампанию/назначения: это разные хранилища. Потеря browser storage теряет локальное состояние; сброс не является серверным backup/restore.
- Примеры ассетов созданы отдельно при разработке; не являются подтверждением live AI. Генерация, анализ и правка реальным API не проверены.
- CP-097 — отдельный эталонный fixture. Нельзя трактовать его эффект как измеренный результат новой кампании.
- Нет полноценного механизма миграций, production-логирования/мониторинга и проверки конкурентного многопользовательского редактирования всех сущностей. CAS применяется к дизайнам.
- Browser cache имеет ограниченные записи, но загрузка исходного набора всё равно занимает память. Старые физические устройства, FPS и батарея не измерялись. Целевой синтаксис сборки не добавляет полифиллы всех новых API.
- Полный E2E, все импорты реальных форматов, экспортированный PNG побайтно и WebMCP end-to-end отдельно не проверены. Некоторые JSX/CSS-файлы записаны длинными строками: физический line count не измеряет сложность.

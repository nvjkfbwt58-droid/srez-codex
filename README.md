# Срез

Независимая локальная реализация аналитической панели и студии купонов по утверждённому design-handoff. Исходники другой реализации не использовались.

## Запуск

Нужен Node.js **24 LTS** и pnpm 11+. Зависимости зафиксированы в `pnpm-lock.yaml`.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

После установки также работает `npm run dev`: одна команда запускает frontend и backend.

- Приложение: **http://127.0.0.1:5178/overview**
- Backend: http://127.0.0.1:4178/api/status
- Порты фиксированы. Если 5178 занят, не останавливайте чужой процесс: измените `server.port` в `vite.config.ts`. При смене портов дополните разрешённые локальные Origin в `server/app.ts`; proxy должен указывать на новый порт backend.

```sh
pnpm test          # расчёты, сервер, PDF, серверный рендер компонентов
pnpm build         # TypeScript + Vite + серверная сборка
pnpm start         # production, приложение и API на 4178
```

Браузерные тесты и настоящие скриншоты, при доступном браузере:

```sh
pnpm exec playwright install chromium
pnpm test:e2e
```

Для `test:e2e` приложение должно уже работать на 5178. Тесты создают данные только в отдельном браузерном профиле Playwright и сохраняют изображения в `screenshots/`. Ручная браузерная проверка выполнена; полный Playwright-сценарий отдельно не запускался. Измерения и границы проверки: [PERFORMANCE.md](PERFORMANCE.md).

## Подключение настоящего AI

1. Скопируйте `.env.example` в `.env` в папке проекта.
2. Впишите `OPENAI_API_KEY` **только в локальный серверный `.env`**. Не вставляйте ключ в чат, браузер или переменную `VITE_*`.
3. Перезапустите `pnpm dev`, затем откройте Настройки → Проверить подключение.
4. В Стиле сети загрузите файлы, выберите референсы → Изучить стиль → проверьте правила → Сохранить стиль.
5. В студии напишите запрос, выберите 1 или 3 варианта и качество. После результата выберите вариант. Следующий текстовый запрос или быстрая правка создаёт новую ветку с исходным изображением.

Настройки по умолчанию:

```dotenv
IMAGE_PROVIDER=openai
IMAGE_MODEL=gpt-image-2.5-sunburst
BRAND_ANALYSIS_MODEL=gpt-4.1
MAX_JOBS_PER_DAY=20
MAX_CONCURRENT_JOBS=2
```

Анализ: официальный SDK OpenAI, Responses API, мультимодальный вход и структурированный ответ, проверяемый общей Zod-схемой. Изображения: `images.generate`; с референсами и для правки: `images.edit`. На каждый вариант выполняется отдельный запрос; автоматические повторные попытки SDK отключены. Текст, логотип, скидка, условия и QR не генерируются внутри картинки.

Модели и методы сверены по [официальному руководству Image API](https://developers.openai.com/api/docs/guides/image-generation) и [документации GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1). Доступность моделей зависит от аккаунта. Наличие ключа в настройках не является доказательством успешного live-вызова.

**Фактический режим этой поставки — без подключённого API.** Готовые картинки имеют отметку «Пример». Новый запрос не подменяется готовым изображением. Реальный live-анализ, генерация и правка не проверены; контрактные тесты используют тестовый транспорт отдельно от рабочего адаптера.

## Возможности

- Обзор с общими фильтрами периода/магазинов, сравнением, KPI, динамикой, таблицами и CSV.
- Продажи: динамика, магазины, товары, сочетания в корзине, время покупок; сортировка, поиск, столбцы, пагинация и экспорт.
- Покупатели: дерево И/ИЛИ/НЕ до трёх уровней, окна истории, сохранённые сегменты, профиль и строки чеков, персональная и сегментная аудитории.
- Кампании: карточки/таблица, черновики, копирование, архив, пять шагов, экономика, бюджет и стабильное назначение контроля.
- Студия: три композиции, три темы, ручной текст, выравнивание, размеры, кадрирование, слои, undo/redo, библиотека вариантов, избранное, PNG/JSON и мобильный preview.
- Стиль сети: изображения, безопасный SVG, PDF, шрифты; источники правил, версии, анализ, утверждение, применение к купону/карте/приложению.
- Локальная касса: проверка назначения, срока, магазина, корзины, маржи, одноразовости; идемпотентные операции и возвраты строк.
- Результаты CP-097: отдельный эталонный fixture с интервалом неопределённости. Будущая симуляция не смешивается с ним.
- Помощник: 12 локальных намерений и общие расчёты, без выдачи локального анализа за подключённую языковую модель.
- CSV-импорт: проверка полей/ссылок/сумм, предпросмотр, ошибки, защита от повторов, отдельный набор.
- Настройки, роли демонстрации, сценарии качества, системная/полная/минимальная анимация, тур и клавиатурный поиск.

## «Показать сценарий»

Кнопка внизу бокового меню открывает инструкцию из 12 шагов: обзор → гипотеза → сегмент → профиль → предложение → стиль сети → дизайн → AI-правка → сроки и бюджет → запуск → касса → результаты.

У каждого шага есть цель, конкретные действия, ожидаемый результат и пояснение. Шаг можно выбрать из списка; подсказку — свернуть или переместить на другую сторону экрана. Если во время сценария открыть свою кампанию или создать копию, следующие шаги кампании и студии будут вести к ней. Шаг с AI можно пропустить, если генерация не подключена. Последний шаг показывает отдельный эталонный эксперимент CP-097.

## Данные и хранение

Демо-время: **14.09.2026, 10:00, Europe/Moscow**. История: 17.05–13.09.2026. Основной период: 17.08–13.09; сравнение: 20.07–16.08. Деньги — целые копейки, без НДС.

Seed 1042026, схема 3: **12 магазинов, 16 000 профилей, 192 SKU, 110 873 операций**. Числа согласованно отличаются от концептуального изображения.

Сегмент: 1 854 → без канала −333 → лимит контактов −167 → магазин/наличие −123 → **1 231 доступный**. Предложение: 615, контроль: 616. Максимум скидок: 30 750 ₽.

- SQLite: `storage/srez.sqlite`. Профили, версии дизайнов, работы, варианты, ключи идемпотентности.
- Изображения/материалы: `storage/assets/`; примеры поставки: `public/assets/`.
- Seed и пользовательский импорт: IndexedDB, ключи `srez-seed-v1` (внутри schemaVersion 3) и `srez-import-v1`.
- Небольшие локальные настройки, кампании, назначения, события и история: `srez-workspace-v1` в localStorage. Студийные запросы/ожидаемые job ID — отдельные ключи с префиксом `srez-`.
- Версии серверного профиля не меняют снимки уже выданных купонов. Применение AI-варианта не запускает кампанию.

PNG-экспорт использует общий `CouponRenderer`, ждёт шрифты и изображения и не содержит персонального токена. Операционный QR есть только у назначенного демо-купона. При полном/частичном возврате купон автоматически не восстанавливается.

## Ограничения

Это локальный демонстрационный продукт: нет реальных касс, рассылок, платежей, production-авторизации и доказательства будущего эффекта. У магазина Бутово в сценарии отсутствуют товары для акции; остальные остатки — демонстрационный снимок. Шаблоны поддерживают до 90 дней действия. Эталонный эксперимент отдельный от генератора чеков.

Браузерная проверка и оптимизация описаны в [PERFORMANCE.md](PERFORMANCE.md). Физические старые устройства и FPS на них не тестировались.

## Ассеты и происхождение

Пять оригинальных фотографических сцен созданы встроенным ImageGen во время разработки. Они не являются результатом вызова API из приложения. Все 5 просмотрены: без запечённых логотипов, текста, условий и UI. Полные промпты и происхождение: `public/assets/provenance.json`.

Исходные референсы изучены как визуальное задание; изображения экранов не встроены в приложение.
